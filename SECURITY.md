# Security

The current development release targets attended use on RHEL 8.10 x86_64. Review the [validation scope](docs/validation.md), verify the release checksum, and begin with a disposable system and Status.

If you find a potential security defect, use GitHub's private vulnerability reporting if available. If there is no private reporting option, open a public issue asking for a private contact channel and leave the technical details out of that request.

Include the script version or tag, an affected operation, and a minimal synthetic example in the private report. Limit attachments to material you are authorized to share. Report paths, snapshot contents, configuration, credentials, archived checklists, and backup artifacts can contain sensitive information.
